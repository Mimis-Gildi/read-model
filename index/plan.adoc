= Wiring the Kotlin harness

The compiler already emits the ESM the fixtures import. Serve that directory. Fixtures import from it.

== The artifact

`harness/build/compileSync/js/main/productionExecutable/kotlin/` — 21 files, VERIFIED on disk:
`read-model-harness.mjs`, `read-model-harness.d.mts`, `read-model-model.mjs`, and the
stdlib / coroutines / serialization / browser / logging siblings with maps. The imports resolve
within the directory, so the directory is the unit that ships.

`read-model-harness.mjs:899`:

[source,javascript]
----
export {
  Measurement as Measurement,
  start as start,
  host as host,
};
----

Webpack still wraps this UMD into `harness.js`; that bundle leaves the path.

== The wiring

`service/build.gradle.kts`, replacing the `:harness` block in `processResources`:

[source,kotlin]
----
from(project(":harness").layout.buildDirectory.dir("compileSync/js/main/productionExecutable/kotlin")) {
    into("harness")
}
----

`:control` is untouched — VERIFIED: no `harness` reference anywhere in `control/src`,
`control/build.gradle.kts`, or its `index.html`; its `control.js` is still UMD and its plain
`<script src>` tag still works.

== The consumers

`pure` and `react-core` already import `/harness/harness.js`; that becomes
`/harness/read-model-harness.mjs`. `:kobweb` takes `implementation(project(":harness"))` and calls
Kotlin directly.

`pure.js:11` still imports `/harness/model.js` — `LEVELS`, `OPEN`, `SHUT`, `LEAF`, `count`. Unported.

== The one API break

`read-model-harness.d.mts:469`:

[source,typescript]
----
export declare const host: { get(): Element; }
----

A Kotlin top-level `val` exports as a getter object. `pure.js:86` does `host.addEventListener(...)`,
which becomes `host.get().addEventListener(...)` — or `host` stops being exported, since
`attach(company, host)` already hands the fixture its container.

== Debugging

`sourceMapEmbedSources = ALWAYS` puts `Harness.kt` inside `read-model-harness.mjs.map`. DevTools
shows the Kotlin with working breakpoints, no bundler frames.

Port 48080 belongs to the IDE debug session.
