= Wiring the Kotlin harness

`binaries.library()` on `:model`, `:harness` and `:control`. The compiler emits a flat, unbundled
ESM tree; the service serves that directory; the fixtures import from it. No webpack on either side.

== The artifact

`<module>/build/dist/js/productionLibrary/` — `read-model-<module>.mjs`, its `.d.mts`, its
`.mjs.map`, the stdlib / coroutines / serialization / browser / logging siblings with maps, and a
`package.json`. The imports resolve by name within the directory, so the directory is the unit that
ships.

`main()` survives the switch: the compiler still emits the call in the module body, so a
`<script type="module">` tag is enough to boot `:control`.

== The wiring

`service/build.gradle.kts`, both blocks in `processResources`:

[source,kotlin]
----
from(project(":control").tasks.named("jsBrowserProductionLibraryDistribution")) {
    into("control")
}
from(project(":harness").tasks.named("jsBrowserProductionLibraryDistribution")) {
    into("harness")
}
----

No `include` filter — the whole distribution ships, siblings included.

`nodejs { }` is gone from all three JS modules. Browser and node library distributions write to the
same `dist/js/productionLibrary`, and two producers on one directory is a Gradle
implicit-dependency failure at `:service:processResources`.

== The consumers

`control/index.html:74` loads `read-model-control.mjs` as a module. `pure` and `react-core` still
import `/harness/harness.js` (`pure.js:10`, `react.js:34`) — that becomes
`/harness/read-model-harness.mjs`. `:kobweb` takes `implementation(project(":harness"))` and calls
Kotlin directly; it has no `:model` dependency yet.

`pure.js:11` and `react.js:35` also import `/harness/model.js` — `LEVELS`, `OPEN`, `SHUT`, `LEAF`,
`count`. Unported. `LEVELS` is model knowledge (child key, `label`, `meta`, `collapsed`); the
glyphs and `count` are presentation shared so all fixtures render identically.

== The seam

`:harness` and `:control` each carry their own `read-model-model.mjs` and stdlib. Two module
identities for the same code — harmless today, since control talks to the fixtures over the socket
and shares no objects with them. It stops being harmless the moment a `:model` distribution is
served alongside and a `KtList` crosses the boundary.

== The one API break

`read-model-harness.d.mts`:

[source,typescript]
----
export declare const host: { get(): Element; }
----

A Kotlin top-level `val` exports as a getter object. `pure.js:86` does `host.addEventListener(...)`,
which becomes `host.get().addEventListener(...)` — or `host` stops being exported, since
`attach(company, host)` already hands the fixture its container.

== Debugging

`sourceMapEmbedSources = ALWAYS` puts the Kotlin inside the `.mjs.map`. DevTools shows `Harness.kt`
with working breakpoints, no bundler frames.

Port 48080 belongs to the IDE debug session.
