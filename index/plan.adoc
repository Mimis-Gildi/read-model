= Riddler's Plan

1. The module list is hardcoded — no, it does not read available tests. Lines 29–31: three <option>s with data-url, plus a hand-written disabled on Kobweb. Vocabulary carries datasets and levels, never modules. So the page holds an opinion about which frameworks exist, which
its own footer says it doesn't, and Module is the third copy of that list after the enum and the mount loop. Adding a fourth framework means editing HTML. data-url is "/" + Module.key + "/" — derivable.
2. levels is dead. The service composes and pushes it; nobody consumes it. Either the fixtures use it to title their tables or it comes out of the frame.
3. Kobweb's disabled is a lie about state, not a fact. Whether a module is launchable is "does a mount answer" — server-side knowledge. Same fix as (1): the vocabulary says which modules are live.
4. The launch button has no idea whether a run is live. Click twice, two runs write into the same cells; the matrix has no notion of which run it's showing. Report.run exists and is discarded by the view.
5. Global mutable latest plus render() reading elDataset.value directly — the filter is a hidden argument. render(latest, elDataset.value) is the honest signature.
6. The —  blank and the isPar string sniff. The service already knows which column is par; the page re-derives it by lowercasing a header. That's the one place the page second-guesses the frame it claims to just render.
7. No error surface. A frame that isn't matrix or vocabulary is silently dropped, and the socket is your debugging channel. A fixture that dies at LOAD looks identical to one that never launched.
